# US-003 — Update documentation and remove deprecated template

> Generated by Doc-Gen Agent on 2026-05-03T00:00:00Z
> Parent: SPEC-001 | Task: T-003 | Status: done

## Who uses this and why

Developers joining the project, and any tooling that reads protocol documentation,
need a single authoritative source for field definitions. Before this story, field
names, types, and required-key lists were written out twice: once as prose in
`docs/protocol/spec-artifacts.md`, and once (differently) in the two template files.
A reader comparing the prose docs to the template would find contradictions. The
deprecated `templates/spec.md.tpl` used field names (`FeatureName`, `PO`,
`CreatedAt`) that are not present in any v1.0.0 schema, creating a risk that someone
would write a spec using those names and wonder why the pipeline could not read it.

## What was built

`docs/protocol/spec-artifacts.md` was updated to make the JSON Schemas the canonical
source of truth. The file now opens with an explicit statement that if the prose ever
drifts from the schemas, the schemas win. For each artifact type, an inline canonical
schema link was added:

- Spec frontmatter → [`spec.schema.json`](../../schemas/v1.0.0/spec.schema.json)
- User Story frontmatter → [`story.schema.json`](../../schemas/v1.0.0/story.schema.json)
- Task frontmatter → [`task.schema.json`](../../schemas/v1.0.0/task.schema.json)
- `stack.md` keys → [`stack.schema.json`](../../schemas/v1.0.0/stack.schema.json)
- `.pipeline-shipped` marker → [`pipeline-shipped.schema.json`](../../schemas/v1.0.0/pipeline-shipped.schema.json)

A "How to validate" section was added with the exact command maintainers run, and a
"Schema version compatibility" section explains how to keep planr CLI and
planr-pipeline in lockstep across upgrades.

`templates/spec.md.tpl` was replaced with a three-line tombstone comment:

```
<!-- This template was removed in SPEC-001 (v0.8.0). -->
<!-- The default-mode shape it described is no longer supported. -->
<!-- Use templates/spec-driven.md.tpl + schemas/v1.0.0/spec.schema.json instead. -->
```

`templates/spec-driven.md.tpl` was preserved unchanged. A conformance audit confirmed
that no file in the `conformance/` directory uses the deprecated field names
`FeatureName`, `PO`, or `CreatedAt`, making the tombstone safe.

## Drift note — spec vs. implementation

The US-003 acceptance criterion states "spec.md.tpl is deleted". The actual
implementation wrote a 3-line tombstone comment file rather than removing the file
from the filesystem entirely. The QA agent accepted this as equivalent because the
file contains no functional content and the tombstone actively guides developers to
the replacement. There is no observable difference for any tool that reads the
templates directory.
