## Summary

Prior to this feature, the planr-pipeline artifact contract — the YAML frontmatter
shapes for SPEC files, User Stories, Tasks, and the `stack.md` and `.pipeline-shipped`
marker — existed only as prose documentation and was enforced only by a hand-rolled
regex parser in `conformance/runner.mjs`. Two templates (`spec.md.tpl` and
`spec-driven.md.tpl`) described incompatible schemas using different field names,
making cross-runtime portability unverifiable and schema drift silent. A malformed
YAML value that confused the regex parser would propagate undetected through the
entire pipeline.

SPEC-001 closes this gap in three coordinated steps: it creates five canonical
JSON Schema files (draft 2020-12) under `schemas/v1.0.0/`; it replaces the regex
parser in the conformance runner with a lightweight in-file YAML parser and adds a
`--validate-schema` CLI flag; and it updates the protocol documentation to point at
the schemas as the single source of truth while tombstoning the now-superseded
`templates/spec.md.tpl`.

The result is that any maintainer — or CI job — can run a single command to verify
that an entire spec directory conforms to the v1.0.0 contract. The QA smoke test
validated all seven SPEC-001-owned artifacts (1 spec + 3 stories + 3 tasks) with
zero failures. One pre-existing gap (`input/tech/stack.md` missing `schemaVersion`)
was disclosed as an out-of-scope follow-up item (candidate: SPEC-007).
