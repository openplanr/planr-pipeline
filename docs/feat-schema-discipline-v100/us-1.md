# US-001 — Create JSON Schema artifacts for planr-pipeline v1.0.0

## Who uses this and why

Maintainers of the planr-pipeline plugin — and the pipeline's own CI jobs — need a
machine-readable, authoritative definition of what a valid spec artifact looks like.
Without such a definition, a developer can write a SPEC file with a misspelled field
name, an unsupported status value, or a missing required key, and the error will
only surface much later (if at all) as a silent data loss or a confusing agent
misbehaviour. This story exists to make those violations detectable immediately.

## What was built

Five JSON Schema files were created under `schemas/v1.0.0/`, one for each class of
planr-pipeline artifact. All five use JSON Schema draft 2020-12, set
`"additionalProperties": false` to catch typo fields, and constrain `schemaVersion`
to the `const` value `"1.0.0"`. Each schema is registered under the
`https://openplanr.dev/schemas/v1.0.0/` namespace.

| Schema file | Artifact validated |
|---|---|
| [`spec.schema.json`](../../schemas/v1.0.0/spec.schema.json) | SPEC-NNN-{slug}.md frontmatter |
| [`story.schema.json`](../../schemas/v1.0.0/story.schema.json) | US-NNN-{slug}.md frontmatter |
| [`task.schema.json`](../../schemas/v1.0.0/task.schema.json) | T-NNN-{slug}.md frontmatter |
| [`stack.schema.json`](../../schemas/v1.0.0/stack.schema.json) | input/tech/stack.md YAML keys |
| [`pipeline-shipped.schema.json`](../../schemas/v1.0.0/pipeline-shipped.schema.json) | .pipeline-shipped marker YAML |

Notable design decisions made in the schemas:

- `task.schema.json` uses a `oneOf` discriminator: UI tasks must pair with
  `frontend-agent`; Tech tasks must pair with `backend-agent` or `db-agent`. This
  enforces the type-to-agent routing contract at the schema level.
- `stack.schema.json` lists `BuildCommand`, `TestCommand`, `Language`, `Framework`,
  and `ORM` as required, but allows the values to be empty strings for stacks where
  some dimensions do not apply (e.g. `ORM: ""` for a no-database plugin).
- `pipeline-shipped.schema.json` uses `pipeline_version` (semver of the plugin) rather
  than `schemaVersion`, because the marker's schema version is implicit in its file
  path. See the schema description field for the rationale.
